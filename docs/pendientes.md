## Deuda técnica

- **El arranque de producción del backend está roto — y el `Dockerfile` también.** `npm run start:prod` corre `node dist/main` (`package.json:12`) y el `Dockerfile` termina en `CMD ["sh", "-c", "npx prisma migrate deploy && node dist/main"]` (línea 24), pero el build **no emite `dist/main.js`**: emite `dist/src/main.js`. Falla al toque con `Cannot find module '...\dist\main'`.
  - **Causa**: `tsconfig.build.json` excluye `node_modules`, `test`, `dist` y `**/*spec.ts`, pero **no `prisma/`**, así que `prisma/seed.ts` entra en la compilación y TypeScript infiere el `rootDir` como la raíz del proyecto (el ancestro común de `src/` y `prisma/`). Por eso `dist/` contiene `prisma/` **y** `src/` en vez de tener `main.js` suelto. Verificado: `ls dist/` → `prisma  src  tsconfig.build.tsbuildinfo`.
  - **Está roto en silencio porque nadie corre el build de producción**: el desarrollo usa `start:dev` (que compila en memoria y no pasa por `dist/`) y el CI corre `lint + build + test`, o sea que el build *pasa* — lo que nunca se ejecuta es el binario resultante.
  - **Es exactamente lo que va a morder al activar el deploy** (ver "Activar el deploy a la nube" en Backend): el contenedor buildea bien y después no levanta.
  - **Dos arreglos posibles**: (a) apuntar el script y el `CMD` a `node dist/src/main` — dos líneas, sin riesgo; (b) agregar `"prisma"` al `exclude` de `tsconfig.build.json` para que `dist/` vuelva a quedar plano y `dist/main.js` exista — más limpio, y no afecta al seed porque corre con `ts-node` sobre el `.ts` (`package.json:81-83`), no sobre el compilado. Conviene decidir junto con el deploy, no antes.
- **`npm run lint` del backend corre `eslint --fix` sobre todo `{src,test}/**/*.ts`**, no sobre el diff — reformatea archivos ajenos al cambio en curso. Revisar `git status` después de correrlo y revertir lo que no sea propio. Considerar acotarlo al diff (`--fix` solo sobre archivos modificados).
- **Renormalizar los finales de línea.** Ya existe `.gitattributes` en la raíz del monorepo (`* text=auto eol=lf`), pero **solo aplica a lo que se toque de ahora en más**: lo ya trackeado conserva sus finales originales hasta correr `git add --renormalize .` y commitear eso aparte. Es un diff grande de una sola línea de comando; queda pendiente decidir cuándo hacerlo. No alcanza a `IALAB-WEB/` ni `chatbot-polo/`, que son repos git independientes y necesitarían el suyo.
